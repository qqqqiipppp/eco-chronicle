## 데이터와 렌더링

`window.ecoRemotePlayers.remotePlayers`는 `Object.create(null)`로 만든 playerId별 컬렉션이다. 각 항목에는 playerId, nickname, theme, joinedAt, appearance, 로컬 임시 position, DOM element 및 렌더링 캐시가 들어간다. 기존 저장 상태 `S`나 로컬 플레이어와 결합하지 않는다.

Presence에는 기존 `playerId`, `nickname`, `theme`, `joinedAt`에 **hair, face, outfit, skin, haircol, direction**만 추가했다. 앞의 다섯 외형 키는 게임의 실제 `S`/`LOOKS` 규격이다. direction은 south로 고정하여 보내며 이동 방향을 추적하지 않는다. 좌표·레벨·장비·경험치·퀘스트는 보내지 않는다.

기존 `customHeadKey`, `sideDir`, `npcTint`와 `refreshHeroArt`의 `data-npc-tint` 갱신 경로를 재사용한다. 기존 body/head 스프라이트, 피부·머리색 팔레트, actor/avatar/nametag CSS를 사용한다. 로컬 외형으로 덮어쓰는 `data-hero`는 사용하지 않는다. 외부에서 받은 외형은 LOOKS 허용 목록으로 검증하며 nickname은 textContent로 표시한다.

자기 playerId와 다른 theme은 제외하고 playerId별로 갱신한다. 한 명이 나가도 나머지 항목과 임시 위치를 유지한다. 별도 맵 레이어는 입력을 받지 않으며 충돌·NPC·몬스터 데이터에 등록하지 않는다. 모달에서는 숨기고 지도 메뉴에서 월드로 돌아오면 다시 붙인다.

임시 위치는 `temporaryPosition()`에서 맵 경계, 시작점, 기존 오브젝트/장애물/NPC와 다른 원격 캐릭터를 피해 선택한다. `setPosition()`이 DOM 위치 적용을 담당한다. 두 함수는 향후 이동 동기화 단계에서 교체/재사용할 수 있도록 분리했다. 현재 위치는 각 브라우저의 표시용 배치이며 브라우저 간 동일 위치를 보장하지 않는다. 안전한 자리가 모두 소진되면 겹쳐 그리는 대신 배치를 보류한다.

## 실제 브라우저 검증

로컬 HTTP 서버와 실제 Supabase 프로젝트를 사용했다. 동일 브라우저 엔진의 독립 탭 **3개**를 동시에 열었다. 서로 다른 외형의 테스트 캐릭터 A/B/C를 서버 응답에만 주입하여 Lv.5 forest에서 시작했다. 저장소나 게임 소스에 테스트용 진입 코드를 넣지 않았다. 테스트 저장은 별도 localhost 포트의 EC9001~EC9003으로 제한했다.

| 상황 | A 화면의 원격 캐릭터 | B 화면의 원격 캐릭터 | C 화면의 원격 캐릭터 |
|---|---|---|---|
| A/B/C forest 접속 | B, C (2명) | A, C (2명) | A, B (2명) |
| B가 게임 지도 UI로 river 이동 | C (1명) | 없음 (0명) | A (1명) |
| B가 지도 UI로 forest 복귀 | B, C (2명) | A, C (2명) | A, B (2명) |
| C 탭 실제 종료 | B (1명) | A (1명) | 종료 |

- 각 화면의 로컬 `#hero`는 1개이며 자기 이름의 원격 캐릭터는 없었다.
- 화면 캡처로 A/B/C가 겹치지 않고 nickname과 서로 다른 외형으로 표시되는 것을 확인했다.
- A 화면에서 B는 robe/long/bold/deep/red, C는 soccer/pony/calm/tan/blonde 스프라이트/팔레트였다. B/C 화면에서도 A와 상대방 외형이 올바르게 반영됐다.
- B 이동 중 C의 표시 위치가 유지됐다. B 복귀 후 재생성됐고 C 종료 시 B는 유지됐다.
- 로컬 키보드 이동으로 A의 x가 298에서 320으로 바뀌었고 원격 캐릭터의 맵 좌표는 유지됐다.
- 가방 정상 열기/닫기, 모달 중 원격 레이어 숨김, 닫은 후 다시 표시를 확인했다.
- 저장 완료 메시지 후 테스트 주입이 없는 시작 페이지로 이동하여 `이어하기 (EC9001)` 실행: 플레이어A, Lv.5, HP 60/100, 골드 60 유지 및 월드 복귀 확인. B 화면에서도 새 페이지의 A 하나만 표시됐다.
- 정상 접속 탭들에서 새 JavaScript error/warn은 발견하지 못했다.
- 별도 탭에서 CDN 스크립트를 응답에서만 제외하여 초기화 실패를 재현했다. 연결 불가 안내와 기존 오류 로그가 표시됐으며 원격 캐릭터 0명 상태에서 게임 이동(x 298 → 307)은 계속 가능했다.

퇴장 표시는 Presence 서버의 변경 전달을 받은 시점에 제거된다. 강제 종료·네트워크 단절에서는 서버의 접속 만료 감지까지 지연될 수 있으며 0ms 제거를 보장하지 않는다. 실제 탭 종료 테스트에서는 후속 확인에서 정상 제거됐다. 모든 브라우저 종류, 대규모 접속, 전체 전투/미니게임 시나리오는 이번 테스트 범위에 포함하지 않았다.

## 오류 및 방어 처리

정상 시나리오에서 수정이 필요한 실행 오류는 발견되지 않았다. CDN 제외 테스트의 `[Supabase] connection test failed: Supabase CDN unavailable...`는 의도한 실패다. 외형 팔레트가 로컬 캐릭터 색으로 덮이지 않도록 기존 개별 팔레트 갱신 경로를 사용했고, 화면 재생성 시 원격 요소 재부착, 이전 채널 콜백 무시, Presence 오류 시 원격 표시 비우기를 적용했다.

JavaScript 구문 검사 및 공백 오류 검사를 통과했다. 저장은 기존 `JSON.stringify(S)` 경로 그대로이며 원격 컬렉션은 S 밖에만 존재한다.

## 다음 단계에서 재사용할 구조

playerId별 컬렉션, Presence 기반 생성/제거, 외형 검증/렌더링, `setPosition()`을 재사용할 수 있다. 다음 단계에서는 승인된 범위에서 좌표 전송 규격과 검증, 전송 주기, 테마/세션 검증 및 이동 표현 방식을 별도로 설계하면 된다. 이번에는 Broadcast, 위치 동기화, 보간, DB 저장, Auth, 전투/장비/퀘스트 공유를 구현하지 않았다.
