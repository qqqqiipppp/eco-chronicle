# 탑 상위 중간보스 화질 점검 — 2026-10-06

## 현재 상태

렌더링 및 손실 압축 개선까지 적용했다. **고해상도 원본 교체는 미완료**이며 사용자가 집에서 이어서 작업하기로 했다. GitHub 최신 `66f5c2f`와 보스 에셋 추가 커밋 `4fd3805`에도 축소 전 생성 PNG/manifest는 없다. `tower-frames`의 PNG들은 256×256으로 이미 정규화된 자료다. 파일명을 유지했고 저해상도 이미지를 업스케일하거나 다시 생성하지 않았다. commit/push 없음.

## 원인과 수정

- 제작 도구가 생성 이미지를 256px 셀로 축소하고 WebP quality 88로 손실 압축했다.
- 실제 캐릭터와 효과의 알파 영역은 프레임별 약 165~224px 폭, 132~210px 높이에 불과했다.
- 전투에서는 반응형 크기에 추가 `scale(1.15)`를 적용했다. 1280×620에서 셀 하나가 365.88px, 1920×1080에서 약 775px까지 확대됐다.
- PNG 40개를 직접 보면 얼굴과 외곽선은 작은 크기에서 선명하다. 고해상도 생성 원본이 없으므로 생성 자체의 흐림 여부는 확정할 수 없다. 웹 화면에서 확대될 때 상세 묘사가 부드러워지는 문제는 여전히 남는다.
- 기존 PNG를 resize 없이 무손실 WebP로 재조립했다. 알파 영역과 5프레임 순서는 유지했다.
- `battle-view.js`에서 1.15배 크기를 실제 레이아웃 박스에 반영했다. 이전 transform-origin(50%, 90%)과 같은 표시 위치를 계산하고 최종 박스를 물리 픽셀에 맞춘다. 플레이어와 기존 몬스터 경로는 유지했다.
- 중간보스의 추가 transform 확대와 겹친 외곽 필터를 제거했다. 한 개의 약한 그림자와 기존 바닥 그림자는 유지한다. CSS background를 사용하며 몬스터 Canvas는 없다.
- 빌더의 새 원본 조립 목표는 832×832(스트립 4160×832)이다. 측정된 데스크톱 최대 775px보다 커야 하기 때문이다. 원본이 작으면 오류로 중단해 업스케일을 막는다. `--pack-existing`은 현재 프레임 크기를 그대로 사용한다.

## 브라우저 확인

실제 로컬 브라우저의 전투 DOM에서 8×5=40프레임을 선택하고 캡처했다. 원본 PNG 40프레임과 브라우저 캡처 40프레임을 직접 검토했다. 동일한 약 366px 크기의 기존 숲 보스(512px 원본)와 비교했다. 기존 보스보다 큰 화면의 상세 묘사는 여전히 부드럽다. 고해상도 원본 복원 전에는 최종 선명도 기준을 충족했다고 볼 수 없다.

- 1280×620: 40프레임 모두 366px 박스, transform 없음, 포즈 변경 중 박스 이동/크기 변경 없음. 얼굴·핵심 소품 식별 가능, 분리 조각 및 알파 본체 잘림 없음.
- 1024×600 / 1280×800 / 1366×900 / 1920×1080: 각각 348 / 521 / 612 / 775px 표시. 반응형 크기 유지. 투명 여백 일부는 박스 밖에 있으나 본체는 화면 안에 있다.
- 100회 프레임 전환: 데스크톱 브라우저 평균 16.62ms, 최대 16.9ms, 포착된 JavaScript 오류 0. 큰 이미지 재생성 전의 테스트이며 실제 Galaxy Tab S5e 성능을 증명하지 않는다.
- **Galaxy Tab S5e 실물 테스트는 하지 않았다.** 1280×620, 1024×600의 유사 가로 viewport로 검증했다.

## 이어서 할 일

1. 집 PC의 `~/.codex/generated_images` 등에 남은 40개 축소 전 생성 PNG와 manifest를 찾는다. 현재 GitHub의 `tower-frames/*.png`를 고해상도 원본으로 간주하면 안 된다.
2. 실제 원본의 선명도를 확인한 뒤 위 빌더로 직접 조립한다. 원본이 작은 경우 확대하지 않는다. 새 이미지 제작이 필요하면 기존 확정 디자인과 각 포즈를 참고해 작업한다.
3. 다시 40프레임과 S5e 유사 viewport, 가능한 경우 실물 기기에서 선명도·로딩·프레임 전환을 확인한다.
