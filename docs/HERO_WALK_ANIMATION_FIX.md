# 주인공 이동 애니메이션 보정

검증일: 2026-09-28. 실제 작업 원본에 몸통 보행 시트와 재생 보정을 적용했다.

## 실제 스프라이트와 재생 구조

- 복장 6종은 아래(`south`), 위(`north`), 왼쪽(`west`) 몸통 시트를 사용한다. 오른쪽은 왼쪽 몸통과 머리를 수평 반전한다.
- 모든 몸통 시트는 792×88 PNG이며, 88×88 칸 9개로 구성된다. 0번은 대기, 1~8번은 보행이고 순서는 `1→2→…→8→1`이다. 프레임 수·크기·방향 이름·반전 방식은 유지했다.
- 머리/얼굴 이미지는 몸통과 별도 레이어다. 기존 머리·얼굴 파일과 선택 값을 그대로 사용한다.
- 기존 월드·농장·채집 필드의 `syncStride()`가 실제 이동 거리에 따라 몸통 프레임을 선택한다. 기존 원격 캐릭터도 이 표시 함수를 재사용한다.

## 좌우 걷기 수정

8개 보행 프레임의 원래 무릎 굽힘, 소매, 옷자락 움직임을 살리고 하체 픽셀의 위치를 보정했다. 앞다리와 뒷다리를 나눌 때 각 프레임에서 양 다리 사이의 투명 영역을 따라 경계를 잡아 바지 줄무늬나 신발 끝이 다른 다리로 잘려 붙지 않게 했다.

발의 수평 보정값은 한 주기에서 `0, 3, 6, 10, 13, 10, 6, 3px`이며 반대 다리에는 반대 부호를 적용한다. 엉덩이 쪽은 고정하고 무릎 아래로 갈수록 보정량을 늘려 양발의 앞뒤 위치가 바뀌게 했다. 뒷다리를 먼저, 앞다리를 나중에 그려 겹치는 순간의 깊이를 유지한다. 5~7번 프레임에서는 반대 발을 원래 접지선에 내려 디디고 지나가는 발은 최대 2px 들어 올린다.

몸과 머리에는 좌우 최대 1px의 체중 이동을 적용했다. 상하 흔들림은 두 구간에서만 최대 1px로 줄여 계속 떠 있는 느낌을 완화했다.

## 상하 걷기 수정

원래 대기 몸통과 어깨 연결을 기준으로 복장별 소매·손 윤곽을 다시 구성했다. 어깨는 고정하고 좌우 팔은 반대 위상으로 최대 1px씩 움직인다. 옷자락을 팔로 잘라 움직이지 않도록 복장별 경계를 사용한다. 원본 보행의 다리 움직임은 유지했다.

걷기 셀 가장자리의 분리된 팔·소매 조각은 새 시트에서 제외했다. CSS로 캐릭터 전체를 가리는 방식은 사용하지 않는다. 대기 0번 셀은 원본 RGBA 픽셀을 직접 복사하며, 18개 모두 원본과 완전히 일치하는 것을 검사했다.

## 재생 보정과 변경 범위

- 이동 거리 12px당 한 프레임이던 보행을 16px당 한 프레임으로 조정했다. 기본 이동 속도 `.19 × dt`는 유지되며, 기본 속도에서 8프레임 주기는 약 0.67초다.
- 정지하면 보폭을 초기화하고 대기 0번·변형 없는 위치로 돌아간다. 다시 이동하면 첫 걸음에서 시작한다.
- 새 애니메이션 루프나 게임 실행 중 이미지 가공은 추가하지 않았다. 제작 때 PNG를 생성해 기존 스프라이트 표시 경로로 읽는다.
- 저장 키·캐릭터 선택 값·전투/미니게임 로직·Presence/Broadcast 데이터와 전송 정책은 변경하지 않았다. 전투용 별도 몸통 시트도 유지했다.

## 실제 게임 테스트

Windows의 Codex 내장 브라우저에서 로컬 시험 서버로 실행했다. 시험 캐릭터를 사용하는 별도 주소의 저장 공간으로 검사했으며, Supabase CDN을 의도적으로 제외해 개인 게임이 계속 실행되는 상태도 확인했다. UI 검사 중 화면 크기와 클릭 좌표의 불일치가 있어 1280×720으로 맞춘 뒤 재검사했다.

| 검사 | 결과 |
|---|---|
| 복장 6종 × 3방향 × 전체 9프레임 확대 비교 | 발 교차, 소매·손 연결, 옷자락 및 분리된 팔 픽셀 확인 |
| 여행복 네 방향 연속 이동 | 각 방향 3.5초, 여러 보행 주기 정상 재생 |
| 방향 전환 및 정지→이동→정지 반복 | 네 방향 모두 정지 시 `0% 0px`, avatar 변형 초기화 확인 |
| 트레이닝복 실제 좌우/위 이동 표시 | 기존 머리와 새 몸통 조합 확인. 걷기 1~8번과 체중 이동 값 순환 확인 |
| 숲 배경 위 접지 | 디딘 발과 지나가는 발의 차이, 기존 그림자와의 관계 확인 |
| 가방 열기/닫기 | 정상 |
| 지도 열기/현재 지역 복귀 | 정상 |
| 기존 저장·불러오기 | 시험 버튼 `save/load PASS` |
| JavaScript 문법 검사 | `game.js`, `visuals.js`, 제작 스크립트 통과 |
| 기존 자동 회귀 검사 | `plogging.test.cjs`, `movement.test.cjs`, `presence35.test.cjs` 모두 통과 |
| PNG 구조 및 대기 픽셀 검사 | 18개 모두 792×88, 대기 셀 원본 RGBA와 완전 일치 |

마지막 네 방향 검사에서 `(298,875)`에서 출발해 오른쪽 `(960.5,875)`, 위 `(960.5,212.5)`, 왼쪽 `(298.1,212.5)`, 아래 `(298.1,875.0)`로 이동했다. 각 구간 종료 시 이동 상태가 해제되고 대기 프레임으로 돌아왔다.

신규 JavaScript 실행 오류는 관찰되지 않았다. `no-cdn` 시험의 기존 Supabase 연결 불가 오류 메시지는 예상된 결과로 분리했다. 실제 Supabase 다중 접속과 Galaxy Tab S5e 실기기 검사는 이번 애니메이션 작업에서 수행하지 않았다.
